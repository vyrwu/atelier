# Maître Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking. Codex without those skills: do the tasks in order, one commit per task, running each task's verification before moving on.

**Goal:** Ship Maître: one AI operator session per atelier instance, opened as a dismissable `M-m` popup, that drives atelier through operator verbs (CLI + `atelier mcp --maitre`), with destroying always confirmed by the human.

**Architecture:** Maître is a workspace record with the reserved slug `maitre`, so it reuses agent launch/resume/swap/hooks. A new `internal/operator` package holds the verbs; `cmd/atelier` exposes them as commands and `internal/mcp` as a second tool set. The popup is a nested tmux client attached to the `maitre` session, whose `key-table` limits atelier's keys to `Esc`/`M-m`/`M-r`/`M-x`.

**Tech Stack:** Go (module `github.com/vyrwu/atelier`), tmux 3.3+, Bubble Tea (existing UI), stdio MCP (existing hand-rolled JSON-RPC in `internal/mcp`).

**Spec:** `docs/superpowers/specs/2026-11-08-maitre-design.md`. Read it first, plus `DESIGN.md` and `CLAUDE.md` (repo rules).

## Global Constraints

- Reserved slug and session name: `maitre` (`core.MaitreSlug`). Display title: `Maître`. Guide file: `~/.config/atelier/MAITRE.md` (under `XDG_CONFIG_HOME`).
- Config key: `maitre_agent` (`"claude"`, `"codex"`, `"grok"`; empty → `agent`).
- Keys: global `M-m` opens; inside Maître `Esc` or `M-m` closes (detach), `M-r` fresh conversation, `M-x` swap. Popup: 70% size, shared rounded grey frame, bottom shortcut legend.
- `wait` default timeout 5m; Grok 50s; hard cap 30m. Destroy-confirm timeout 60s. Paste settle before Enter 150ms. `read` default 60 lines.
- Maître's MCP tool timeout: 600s (Codex `tool_timeout_sec = 600`; Claude env `MCP_TOOL_TIMEOUT=600000`).
- Destroying (`delete`, `purge`) when `ATELIER_SESSION=maitre`: always atelier's tmux confirm on a client attached to `maitre`; `--yes`/`--force` ignored; no client → refuse; no/timeout → refuse.
- Maître never appears in `M-s`, Trash, `ls`, `spaces`, `purge`, `gc` adoption, the PR poll, or the splash count; it does count in the attention badge.
- Tests cover the headless core only; nothing new shells out to tmux/gh/agents in tests, and no abstraction is added just to mock tmux (inject plain funcs where a test needs a seam, as specified per task).
- Commits: Conventional Commits (release-please parses them), e.g. `feat(maitre): …`. No `[PLA-XXX]` prefix in this repo.
- Before the final commit: `mise trust && mise run ci` must pass.

## Review Focus

1. Lost Maître record with its directory still on disk → `gc` must not adopt `maitre` as an ordinary space (it doesn't, because Maître links `MAITRE.md`, not the workspace guide); the next `M-m` recreates the record. Test in Task 1.
2. A Maître tool aimed at an unknown slug, a retired slug, or `maitre` itself → a clear refusal, never an action on the wrong space. Tests in Task 2.
3. `send` text that starts with `-` or looks like a tmux key name (`-h`, `Enter`, `C-c`) → typed literally. Test in Task 4.
4. Destroy requested while the popup is hidden, or while two clients view Maître → refuse when none; ask the first attached client otherwise; Esc/timeout = refuse. Tests in Task 6.
5. `wait` while spaces are created or deleted mid-wait, or a status file is missing → a new space reaching idle counts, a deleted one is ignored, no spaces → returns empty at the timeout. Tests in Task 5.

Implementation adjustments from the sketches:

- `Retire` shares the state lock with launch and purge and reports stop errors.
  UI retirement uses the same operation.
- `display-menu` blocks until selection, so confirmation gets its own
  60-second process context, rather than tmux's normal five-second timeout.
  A unique transient option records the answer; late selections cannot reuse
  an expired confirmation. Session option targets omit the `=` prefix, which
  tmux 3.5a rejects for `set-option`.
- Maître reuses the existing `execTmux` attach helper. Startup is serialized so
  simultaneous openers cannot respawn each other's conversation.
- MCP environment now pins the instance socket and provider directories, and
  the tmux session receives the full agent identity. Codex project preparation
  preserves unrelated config instead of replacing the whole file.
- Generated titles use a conditional state update so they cannot overwrite a
  rename made while the title model was running.
- Headless tests cover the state, scope guards, snapshots, status transitions,
  argument validation, config merges, attention, and bindings. Operations that
  invoke tmux were checked manually, following the repository testing rule.

### Adversarial and Copilot review

The first Copilot review on PR #117 raised five actionable findings. All were
addressed: the MCP reader now accepts cancellation while tools run; creation
publishes its slug after initial display setup; generated and operator titles
publish under the same state lock; CLI `send` accepts literal text after `--`;
and focus restores the title and status marker when reviving a stopped session.
Title backfill also reads current state under that lock so stale UI snapshots
cannot undo a rename.

Adversarial checks found two further issues. Literal screen input now uses
tmux's bracketed paste via stdin, preserving multiline prompts and avoiding
argument parsing. Recovering a missing Maître record keeps creation unknown
and recovers the provider from live metadata or transcripts, preserving older
conversations' eligibility for resumption.

Headless regressions cover transport cancellation/disconnection, wait
cancellation, delimiter parsing, conditional naming and Maître recovery.
Manual checks in `.maitre-review/` verified that a cancelled MCP wait leaves
`tools/list` responsive; flag-like multiline text arrives as one exact bracketed
paste with no leftover buffer; focusing a stopped native Codex session restores
its stored title and idle marker; and reopening a record-less live Maître
preserves its process and recovers its provider. These checks use disposable
sockets and isolated state, config and provider directories.

Copilot's second pass confirmed the first five fixes and identified three
further lifecycle issues. Restart now takes the existing handoff lock and
checks its pending reservation before reading the provider. CLI delete/retire
reject their enclosing space, preventing session shutdown from interrupting
cleanup or state persistence. Opening a blocked Maître acknowledges attention
in the same way as visiting an ordinary space. Headless regressions cover
pending/active handoff rejection and both CLI identity environment variables.
Restart also invalidates expired launch tokens so a delayed child cannot take
over afterward. Manual tmux checks verify attention acknowledgment and that a
plain shell without atelier identity variables refuses to stop itself while
still retiring and deleting another space successfully.

The third Copilot pass confirmed those lifecycle fixes and found that purge's
CLI subprocess did not receive MCP cancellation. Purge now receives the request
context and interrupts its child cooperatively. Maître's purge CLI propagates
that cancellation into its menu and deletion checks; the state lock protects
the final cancellation check before any deletion begins. A deletion already
started finishes its cleanup and state write before exiting. Direct MCP delete
also checks cancellation at that boundary, including after a late Yes.
Headless tests verify canceled purge and late-confirmation deletion preserve
files and state. Manual MCP checks verify cancellation and stdin disconnection
dismiss purge approval, preserve the target, and release the connection; the
next serialized tool call completes promptly.
Cancellation and timeout explicitly close the tmux menu overlay as well as
invalidating its approval; a terminal capture verifies the menu is cleared.

Copilot's fourth pass reported no open findings but requested assessment of
restore/status concurrency. A headless regression reproduced a stale second
restore resetting an already-working agent to idle. The retired-state check
now happens under the same lock as the status change. Agent revival also
checks current state, provider and session existence under the launch lock,
so concurrent openers cannot respawn each other's newly started agent.
Manual checks admitted one of two concurrent restores, refused the stale
second call, and verified concurrent openers and subsequent reopening of the
