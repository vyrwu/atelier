# Maître Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Codex without those skills: do the tasks in order, one commit per task, running each task's verification before moving on.

**Goal:** Ship Maître: one AI operator session per atelier instance, opened as a dismissable `M-m` popup, that drives atelier through operator verbs (CLI + `atelier mcp --maitre`), with destroying always confirmed by the human.

**Architecture:** Maître is a workspace record with the reserved slug `maitre`, so it reuses agent launch/resume/swap/hooks. A new `internal/operator` package holds the verbs; `cmd/atelier` exposes them as commands and `internal/mcp` as a second tool set. The popup is a nested tmux client attached to the `maitre` session, whose `key-table` limits atelier's keys to `M-m`/`M-r`/`M-x`.

**Tech Stack:** Go (module `github.com/vyrwu/atelier`), tmux 3.3+, Bubble Tea (existing UI), stdio MCP (existing hand-rolled JSON-RPC in `internal/mcp`).

**Spec:** `docs/superpowers/specs/2026-11-08-maitre-design.md`. Read it first, plus `DESIGN.md` and `CLAUDE.md` (repo rules).

## Global Constraints

- Reserved slug and session name: `maitre` (`core.MaitreSlug`). Display title: `Maître`. Guide file: `~/.config/atelier/MAITRE.md` (under `XDG_CONFIG_HOME`).
- Config key: `maitre_agent` (`"claude"`, `"codex"`, `"grok"`; empty → `agent`).
- Keys: global `M-m` opens; inside Maître `M-m` closes (detach), `M-r` fresh conversation, `M-x` swap. Popup: `-w 80% -h 80% -T " Maître "`.
- `wait` default timeout 5m; Grok 50s; hard cap 30m. Destroy-confirm timeout 60s. Paste settle before Enter 150ms. `read` default 60 lines.
- Maître's MCP tool timeout: 600s (Codex `tool_timeout_sec = 600`; Claude env `MCP_TOOL_TIMEOUT=600000`).
- Destroying (`delete`, `purge`) when `ATELIER_SESSION=maitre`: always atelier's tmux confirm on a client attached to `maitre`; `--yes`/`--force` ignored; no client → refuse; no/timeout → refuse.
- Maître never appears in `M-s`, Trash, `ls`, `spaces`, `purge`, `gc` adoption, the PR poll, or the splash count; it does count in the attention badge.
- Tests cover the headless core only; nothing new shells out to tmux/gh/agents in tests, and no abstraction is added just to mock tmux (inject plain funcs where a test needs a seam, as specified per task).
- Commits: Conventional Commits (release-please parses them), e.g. `feat(maitre): …`. No `[PLA-XXX]` prefix in this repo.
- Before the final commit: `mise trust && mise run ci` must pass.

## Review Focus

1. Lost Maître record with its directory still on disk → `gc` must not adopt `maitre` as an ordinary space (it doesn't, because Maître links `MAITRE.md`, not the workspace guide); the next `M-m` recreates the record. Test in Task 1.
2. A Maître tool aimed at an unknown slug, a retired slug, or `maitre` itself → a clear refusal, never an action on the wrong space. Tests in Task 2.
3. `send` text that starts with `-` or looks like a tmux key name (`-h`, `Enter`, `C-c`) → typed literally. Test in Task 4.
4. Destroy requested while the popup is hidden, or while two clients view Maître → refuse when none; ask the first attached client otherwise; Esc/timeout = refuse. Tests in Task 6.
5. `wait` while spaces are created or deleted mid-wait, or a status file is missing → a new space reaching idle counts, a deleted one is ignored, no spaces → returns empty at the timeout. Tests in Task 5.

```markdown
# Maître

You are Maître, the operator of this atelier instance. You run spaces for the
human the way they would: start them, check on them, answer their agents, tidy
up. You do not write code or create worktrees yourself — every piece of work
happens in a space.

## Tools

Use the `atelier` MCP tools (or the same verbs as `atelier <verb>` in a shell):
list_spaces, create_space, rename_space, retire_space, restore_space,
delete_space, purge_spaces, swap_agent, read_screen, send_input,
wait_for_change, focus_space.

## How to work

- Read a space's screen before typing to it. Answer what it actually asks.
- To start work, create a space with a clear, self-contained intent: the repo,
  the goal, and how to know it's done.
- Waiting for spaces: call wait_for_change, never poll in a loop.
- Approve routine permission prompts in spaces (tests, builds, edits, git
  commits, opening PRs). Ask the human before approving anything destructive or
  irreversible: force-pushes, deleting data or branches, production changes.
- Deleting and purging always ask the human through atelier. If it reports they
  aren't looking, tell them what you wanted to delete and why.
- When the human wants to see a space, use focus_space.
- Keep replies short: you live in a small popup.
```
